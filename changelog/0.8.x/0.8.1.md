# 0.8.1 — 2026-11-15

## Added

- **`state` and `zip_code`** on `epa_echo_search_facilities` and `epa_echo_search_violations` take a list or a comma-joined string, up to 100 state codes and 200 ZIP codes, and match any of them; a single code as a string works as before. ([#73](https://github.com/cyanheads/epa-mcp-server/issues/73))
- **`epa_echo_get_facility`** returns `effluentExceedances`, `rcraViolations`, `highPriorityViolations`, and `programIds`; the first two page with `effluent_exceedances_limit`/`_offset` and `rcra_violations_limit`/`_offset`, the other two come whole. ([#75](https://github.com/cyanheads/epa-mcp-server/issues/75))
- **`epa_superfund_get_site`** and `epa://superfund/{site_id}` accept an EPA ID as well as a SEMS site ID; **`epa_superfund_search_sites`** takes `name`. ([#76](https://github.com/cyanheads/epa-mcp-server/issues/76))
- **Both TRI tools** return `chemicalId` and `casNumber` and accept `chemical_id` for an exact match: a CAS number, a category code such as `N420`, or a returned `chemicalId`. ([#77](https://github.com/cyanheads/epa-mcp-server/issues/77))
- **`distanceMiles`** on each proximity row of `epa_echo_search_facilities` and `epa_superfund_search_sites`. ([#80](https://github.com/cyanheads/epa-mcp-server/issues/80))

## Changed

- **Count inputs** drop the 5,000 schema maximum and default to 25; a value above a tool's cap is served at the cap with a `limitNotice`, and `EPA_CLAMP_LIMITS=false` makes each cap a strict maximum. ([#78](https://github.com/cyanheads/epa-mcp-server/issues/78))
- **Caps** are sized near a 1 MB page: 2,500 on the ECHO facility and Superfund searches, 2,000 on `epa_echo_search_violations`, 1,000 on the water search, 699 on both TRI tools, and on `epa_echo_get_facility` 5,000 inspections and 3,000 drinking-water violations. ([#78](https://github.com/cyanheads/epa-mcp-server/issues/78))
- **`epa_echo_get_case`** pages `facilities` and `enforcementConclusions` (`facilities_limit` 25, `enforcement_conclusions_limit` 10, with matching offsets); a default call returns the first page with totals and next offsets. ([#79](https://github.com/cyanheads/epa-mcp-server/issues/79))
- **The ECHO search deadline's recovery hint** says to split a long state or ZIP list across calls. ([#73](https://github.com/cyanheads/epa-mcp-server/issues/73))
- **Output-schema descriptions** are trimmed from 38,630 B to 25,455 B across all tools; this misses the 20,000 B target because what remains are facts a caller acts on. ([#81](https://github.com/cyanheads/epa-mcp-server/issues/81))
- **Upstream HTTP error bodies** stay in the server log and no longer reach `error.data`.

## Fixed

- **`epa_tri_get_facility_releases` `facility_id`** rejects a 12-digit Registry ID, a value of any other length, and a number, naming the 15-character form; 0.8.0 answered each with an empty success. ([#77](https://github.com/cyanheads/epa-mcp-server/issues/77))
- **A raised `limit` beside near-limit text filters** on the DMAP searches is served at the largest limit that fits DMAP's request line, with a notice; 0.8.0 failed with `filter_too_long`.
- **An unreadable `.env`** (a directory, for example) stops startup with the configuration-error banner instead of a stack trace.
- **The Claude and Codex plugin manifests** forward `AIRNOW_API_KEY`, `EJSCREEN_API_BASE_URL`, and `EPA_CLAMP_LIMITS`, so a plugin install can enable AirNow.
