# 0.8.0 — 2026-11-01

## Added

- **`epa_echo_get_case`** retrieves a civil enforcement case by case number with its facilities (one per Registry ID, each accepted by `epa_echo_get_facility`), defendants, laws, pollutants, milestones, and conclusions. A criminal `CR_` number fails as `criminal_case` before any request, and an unknown number as `case_not_found`. ([#59](https://github.com/cyanheads/epa-mcp-server/issues/59))
- **`epa_echo_search_violations`** returns `caseStatus`, `enforcementOutcome`, `leadAgency`, `primarySection`, `closedDate`, and the state/local penalty, cost-recovery, compliance-action, and supplemental-project dollar fields; `program` accepts `EPCRA`. ([#60](https://github.com/cyanheads/epa-mcp-server/issues/60))
- **`epa_echo_search_facilities`** takes `facility_name`, `county`, `county_fips`, and `naics`, and returns `triFacilityIds` on each row; `epa_echo_get_facility` returns `naics`. ([#61](https://github.com/cyanheads/epa-mcp-server/issues/61))
- **`epa_echo_get_facility`** returns `drinkingWaterViolations[]`, paged with `drinking_water_violations_limit` and `drinking_water_violations_offset`, and `registry_id` (also on `epa://facility/{registry_id}`) accepts a PWSID, TRI facility ID, NPDES permit, or RCRA handler ID. ([#62](https://github.com/cyanheads/epa-mcp-server/issues/62))
- **`epa_water_search_systems`** takes `county` (with `state`) and `active_only`. ([#63](https://github.com/cyanheads/epa-mcp-server/issues/63))
- **Paging** on every list: `offset` in, `nextOffset` in `enrichment` exactly when more records follow. `epa_tri_get_facility_releases` gains `limit`, and `epa_echo_get_facility` gains `inspections_limit` and `inspections_offset`. ([#53](https://github.com/cyanheads/epa-mcp-server/issues/53))
- **`effectiveQuery`** on the five search tools states the filters as sent (normalized values, match mode, defaults), on results and empty pages, with a `Query:` line in `content[]`. ([#70](https://github.com/cyanheads/epa-mcp-server/issues/70))
- **TRI tools** return `totalOnSiteReleasesInLbs`, the sum of the per-medium fields; `epa_tri_search_releases` also returns `registryId` and `parentCompany`. ([#67](https://github.com/cyanheads/epa-mcp-server/issues/67))
- **`epa_ejscreen_get_scores`** returns `usAverage` on both demographic indices, and the index descriptions define their z-score scale. ([#65](https://github.com/cyanheads/epa-mcp-server/issues/65))

## Changed

- **`totalReleasesInLbs`** is renamed `oneTimeReleaseInLbs` on both TRI tools (Form R Section 8.8, already counted in the per-medium figures); update consumers reading the old name. ([#67](https://github.com/cyanheads/epa-mcp-server/issues/67))
- **Superfund and water `totalCount`** is optional and means records matched before `limit` and `offset`: Superfund returns it only for proximity searches, and water omits it when more records follow (v0.7.0 returned the count returned). ([#53](https://github.com/cyanheads/epa-mcp-server/issues/53))
- **ECHO facility and violation searches** reject comma- or space-separated `state` and `zip_code` lists with -32602 (v0.7.0 answered `WA,OR` and `98108,98109`); multi-value filters are tracked separately. ([#56](https://github.com/cyanheads/epa-mcp-server/issues/56), [#73](https://github.com/cyanheads/epa-mcp-server/issues/73))
- **ECHO `zip_code`** rejects the 4-character code `3198`; `zip_code` on Superfund and water rejects stored non-ZIP forms (Canadian postal codes, `ddddd-ddd`), and a `ddddd-ddd` record is still found by its 5-digit prefix. ([#56](https://github.com/cyanheads/epa-mcp-server/issues/56))
- **`limit`** above a tool's cap clamps to the cap with a `limitNotice` (up to 5,000; v0.7.0 rejected it). ([#53](https://github.com/cyanheads/epa-mcp-server/issues/53))
- **Result order** is deterministic: Superfund administrative searches by site ID, water by PWSID, TRI single-year lookups newest first; same-date inspections in `epa_echo_get_facility` may reorder. ([#53](https://github.com/cyanheads/epa-mcp-server/issues/53))
- **`epa_water_search_systems` `has_violation`** keeps the systems ECHO flags with a current SDWA violation, which clears many SDWIS rows still marked unresolved. ([#52](https://github.com/cyanheads/epa-mcp-server/issues/52))
- **`epa_tri_search_releases`** accepts a padded `state` such as ` WA ` and returns it uppercased. ([#56](https://github.com/cyanheads/epa-mcp-server/issues/56))
- **`epa_ejscreen_get_scores`** returns `coverage.valid: false` with a note for points outside EJAM's US bounds (v0.7.0 failed with an R error) and for buffers holding no Census block; a zero-resident buffer keeps its state and population 0 and no longer reads as outside coverage. ([#64](https://github.com/cyanheads/epa-mcp-server/issues/64))
- **DMAP input rejections** carry the reason `unmatchable_filter` or `filter_too_long` with a recovery hint on the TRI, Superfund, and water tools and `epa://superfund/{site_id}`. ([#69](https://github.com/cyanheads/epa-mcp-server/issues/69))
- **Malformed upstream JSON** fails as a serialization error after one request in the DMAP, ECHO, and EJAM services (v0.7.0 retried four times and reported a validation error). ([#72](https://github.com/cyanheads/epa-mcp-server/issues/72))
- **Empty-result messages** no longer restate the filters; `effectiveQuery` carries them. ([#70](https://github.com/cyanheads/epa-mcp-server/issues/70))

## Removed

- **`cases[].facilityName`, `cases[].registryId`, and `cases[].state`** are removed from `epa_echo_search_violations` output; they were never populated. Use `epa_echo_get_case` for a case's facilities. ([#59](https://github.com/cyanheads/epa-mcp-server/issues/59))
- **`compliance.mediaStatusCode`, `compliance.mediaStatusDescription`, and `waterCompliance.programId`** are removed from `epa_echo_get_facility` output; they were never populated. ([#68](https://github.com/cyanheads/epa-mcp-server/issues/68))

## Fixed

- **TRI surface impoundment releases** (`SI 5.5.3A`, `SI 5.5.3B`) now count in `releasesToLandInLbs` on both TRI tools. ([#51](https://github.com/cyanheads/epa-mcp-server/issues/51))
- **Malformed `state`** on Superfund, water, and TRI searches (`Washington`) fails with a validation error instead of an empty result, and TRI `"  "` instead of an HTTP 500 after four attempts; a code outside the shared set such as `ZZ` fails as `invalid_state`. ([#56](https://github.com/cyanheads/epa-mcp-server/issues/56))
- **Malformed ECHO `state` and `zip_code`** (`Washington`, `W`, `9810`, `abcde`) fail validation instead of returning an empty result. ECHO codes outside the USPS set still search as written. ([#56](https://github.com/cyanheads/epa-mcp-server/issues/56))
- **`epa_airnow_get_conditions`** rejects a non-ISO or impossible `forecast_date` instead of returning an empty "No forecast valid" result. ([#56](https://github.com/cyanheads/epa-mcp-server/issues/56))
- **ZIP+4 inputs** search their 5-digit ZIP on every tool, and Superfund and water `zip_code` match by prefix, so sites and systems stored under a ZIP+4 are found. ([#56](https://github.com/cyanheads/epa-mcp-server/issues/56), [#63](https://github.com/cyanheads/epa-mcp-server/issues/63))
- **Overlong Superfund `city` and TRI `county` or `chemical_name`** fail with `filter_too_long` instead of an empty result. ([#69](https://github.com/cyanheads/epa-mcp-server/issues/69))
