# 0.2.0 — 2026-06-21

## Added

- **`epa_search_facilities` proximity search** — new `latitude`, `longitude`, and `radius_miles` inputs (radius capped at 100 mi), mapped to the ECHO `p_lat` / `p_long` / `p_radius_mi` parameters. A complete latitude+longitude+radius_miles triple is a valid geographic filter alongside `zip_code` / `state` / `city`. ([#14](https://github.com/cyanheads/epa-mcp-server/issues/14))
- **`incomplete_proximity` error** — supplying only one or two of the three proximity fields raises a `ValidationError` before the upstream call. `latitude` / `longitude` of `0` (equator / prime meridian) are valid and presence is tested with `!== undefined`, never a truthy check. ([#14](https://github.com/cyanheads/epa-mcp-server/issues/14))

## Changed

- **`AIRNOW_API_KEY` is now optional** — when unset (or empty / whitespace-only), the server starts without `epa_get_air_quality` and skips AirNow init, registering the 7 keyless ECHO/DMAP tools (`coreToolDefinitions`); set the key to enable the full 8-tool surface. `server.json` and `manifest.json` mark the variable optional, and server instructions drop the AirNow guidance when the tool is disabled. ([#13](https://github.com/cyanheads/epa-mcp-server/issues/13))
