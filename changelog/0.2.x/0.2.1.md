# 0.2.1 — 2026-07-10

## Added

- **`epa_get_tri_releases` per-medium release breakdown** — four new optional fields on each release record: `releasesToAirInLbs`, `releasesToWaterInLbs`, `releasesToLandInLbs`, `releasesToUndergroundInjectionInLbs`, summed from a new batched `tri.tri_release_qty` query joined on `doc_ctrl_num`. Completes the four-way media split the README already documented. ([#15](https://github.com/cyanheads/epa-mcp-server/issues/15))

## Changed

- **`totalReleasesInLbs` description** clarified as TRI's one-time / non-routine release quantity (spills, accidents) — a distinct category from the new routine per-medium fields, not their sum. Value and field name unchanged.
- **Supply-chain hardening** — `bunfig.toml` blocks packages published <3 days ago (`minimumReleaseAge`, `@cyanheads/mcp-ts-core` exempted for same-day framework adoption) and scans installs via `@socketsecurity/bun-security-scanner`; new `LICENSE` (Apache-2.0), `.github/SECURITY.md`, `.gitattributes`; `Dockerfile` pins `oven/bun:1.3.14` (was floating `1.3`), adds BuildKit cache mounts, and runs `--ignore-scripts` on the build stage.
- **`devcheck`** adds a `check-dependency-specifiers.ts` step (rejects floating `latest` / `*` / dist-tag dependency specifiers) and extends packaging-lint to cover plugin marketplace manifests; framework skills re-synced to `.claude/skills/`.

## Fixed

- **`epa_search_facilities` proximity search** — ECHO requests now send `p_radius` instead of the unrecognized `p_radius_mi`, so `latitude` + `longitude` + `radius_miles` queries return facilities instead of ECHO's "p_radius required" error. ([#16](https://github.com/cyanheads/epa-mcp-server/issues/16))
