# 0.6.0 — 2026-10-24

## Changed

- **Tool names** now follow `epa_<group>_<verb>_<object>`; update stored calls and workflows using the mapping below. Old names have no aliases. ([#20](https://github.com/cyanheads/epa-mcp-server/issues/20))

| Previous name | Replacement |
|:--|:--|
| `epa_search_facilities` | `epa_echo_search_facilities` |
| `epa_get_facility` | `epa_echo_get_facility` |
| `epa_search_violations` | `epa_echo_search_violations` |
| `epa_search_tri_releases` | `epa_tri_search_releases` |
| `epa_get_tri_releases` | `epa_tri_get_facility_releases` |
| `epa_search_superfund` | `epa_superfund_search_sites` |
| `epa_search_water_systems` | `epa_water_search_systems` |
| `epa_get_air_quality` | `epa_airnow_get_conditions` |
| `epa_get_ejscreen` | `epa_ejscreen_get_scores` |

- **Development and Docker** use Bun 1.4.3 → 1.4.4.

## Fixed

- **`epa_superfund_search_sites`** exhausts latitude/longitude candidate pages before exact-distance filtering and nearest-first ordering, removing the 500-candidate cutoff; notices disclose matches omitted by `limit`. ([#48](https://github.com/cyanheads/epa-mcp-server/issues/48))
- **Complete proximity scans** share the existing 50-second deadline; broad searches can now time out instead of returning capped partial results. Repeated candidate pages fail as `ServiceUnavailable`. ([#48](https://github.com/cyanheads/epa-mcp-server/issues/48))
- **Combined city/proximity filters** consume 89 more request-line bytes with longitude filtering and sorting in the Seattle 25-mile example; shorten filters rejected by DMAP's 4,094-byte bound (3,891 ASCII city characters accepted, 3,892 rejected). ([#48](https://github.com/cyanheads/epa-mcp-server/issues/48))
