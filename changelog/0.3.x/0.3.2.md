# 0.3.2 — 2026-09-19

## Changed

- HTTP defaults to stateless when MCP_SESSION_MODE is unset; an explicit environment value still overrides it (#22).
- **Environment configuration** treats empty and whole-placeholder values as unset through `@cyanheads/mcp-ts-core`, so optional AirNow configuration stays disabled and the EJScreen endpoint uses its default.
- **Runtime baseline** now requires Bun 1.4 or later; this is a runtime migration with unchanged tool contracts.
- **Tool arguments** accept case-style aliases for declared keys and ignore the framework's fixed client metadata-key list; other unknown keys still return `InvalidParams`.
- **Error responses** include reason and retryability terms when available and preserve recovery guidance for client-side branching.
- **Development workflows** moved from `skills/` to `framework-skills/`, and package, bundle, and manifest checks follow the current framework delivery rules.
- **Project documentation and issue forms** now describe the resource surface, reporting route, security advisory path, and current runtime values.

## Fixed

- **AirNow, ECHO, DMAP, and EJAM failures** no longer expose upstream request URLs in MCP error data. [#23](https://github.com/cyanheads/epa-mcp-server/issues/23)
- **Invalid tool arguments** now use the framework's production `InvalidParams` error envelope with structured error content.
- **EJAM non-400 HTTP failures** now use the framework's upstream HTTP classification, while invalid coordinates retain their validation error.

## Security

- **AirNow error handling** no longer returns a credential-bearing upstream URL to clients. [#23](https://github.com/cyanheads/epa-mcp-server/issues/23)
